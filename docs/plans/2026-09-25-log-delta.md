# The log's delta against last life — plan (2026-09-25)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A one-time row's log line shows, in its own column beside the time,
how much sooner or later it finished than in the last life that finished it.

**Architecture:** The engine stamps each one-time completion's run tick into
`GameState.finishedAt` (this life, reset at rebirth). `rebirth` merges it into
`GameState.lastFinish` (every row's most recent finish, kept across lives). At
completion the engine puts `lastFinish[id]` on the `completed` event as
`lastAt`. The log computes the delta from the line's own `at` and the event's
`lastAt` and renders it in a pinned column. Saves stay format 1.

**Tech stack:** TypeScript, React 19, Vitest (+ jsdom for components). No new
dependency.

**Spec:** `docs/specs/2026-09-25-log-delta.md` (#75). Mockup:
`docs/mockups/2026-09-25-log-delta.html`, variant E. Branch
`feature/log-delta`.

**Status (2026-09-25): shipped to main as 1cb3679 (0.3.3, squashed), live on GitHub Pages; the user approved the deltas in Chrome. The same release removed level-up lines from the log at the user's ask. Three plan panel rounds (the third text-level only, so executed by the standing rule); code panel: round 1 found a vacuous save test, an untested finite check and a screen-reader gap (fixed in 33f6d4c), round 2 two test gaps (fixed in 1e02eb9); 850 tests.**

**Revision 1 (panel round 1: design against code, plan against design,
naysayer).**
- **Storage moved from a per-life map on `LifeRecord` to one persisted
  `GameState.lastFinish`** (naysayer). The per-life map was justified by a
  chart the spec excludes; the single map is a lookup by key, leaves
  `LifeRecord` and its five test fixtures untouched, grows by rows rather than
  lives × rows, and removes the two defects the reviewers found in the old
  shape: an import cycle (`queue.ts` calling a helper in `rebirth.ts`, which
  imports `queue.ts`) and a crash when the dev handle loads `lives` records
  without the field.
- **`runTicks` at completion is settled** (all three): `step` raises it before
  `work`, so the stamp equals the line's `at`. The "check first" step is gone.
- **`isLine` checks `lastAt`** (naysayer; the plan had said no change): a
  hand-edited `lastAt: "x"` would render `NaN:NaN`.
- **Property invariant added** (naysayer): `finishedAt` keys are all in
  `completedOneTime`, values at most `runTicks`.
- **Widths measured, not guessed** (naysayer, Reviewer B): at 11px Menlo
  `100:00` and `+99:59` are 39.7px and `+999:59` is 46.4px. The time column is
  pinned at **40px** (it clipped a life past 100 minutes at the mockup's 38) and
  the delta column at **47px** (fits any life under 1000 minutes). The mockup's
  42px would clip a delta over 99:59.
- **Tests made to fail without the fix** (Reviewer B): the dev-handle load
  test asserts the empty maps right after `load`; `deadLife()` gets a
  non-empty `finishedAt` so the RESETS check is not `{}` against `{}`; engine
  tests unpause (`newState` starts on `system`) and assert against the
  emitting step's `runTicks`.
- **Parallel Tasks 2 and 3 share one tree** (Reviewer B): each stages only its
  named paths and treats a red gate in the other task's files as not its own.
- Every gate names its commands, including `npm run test:hooks`; each test step
  runs red before the implementation; Task 4 states its pass conditions and
  uses the chrome-verify skill for the port; `Log.test.tsx` exists and is
  extended; the formatter is `splitDelta` and reuses `format.ts`'s `minutes()`.

**Accepted risks.**
1. *Last life is a noisy baseline* (naysayer). Objection: life 6 builds the
   satchel first and shows a red `+1:40` on the hull for a deliberate choice,
   then life 7 shows a large green delta against it. Cheaper alternative:
   compare against the best time, which only moves one way. Rejected: the
   user's words are "last time it was 2:30", and a best-time baseline is a
   different feature; the handoff names this effect so the user meets it
   before Chrome, not during.
2. *No per-life history for a future chart* (follows from Revision 1).
   Objection: a later chart of one row's time across lives would have no
   history from before it ships. Cheaper alternative: store a per-life map on
   `LifeRecord` now, as the first draft did. Rejected: no such chart is asked
   for or filed; the per-life map costs lives × rows on an uncapped, saved,
   frequently rewritten list, and brought a crash path and an import cycle with
   it; if the chart is built, its history starts that day.
3. *A mid-life upgrade shows a blank delta once* (naysayer, spec section 3;
   corrected in Revision 2). Objection: a life loaded from a pre-change save
   has no `finishedAt` for rows it finished before the load, so the next life
   shows no delta for those rows although a life did finish them. Cheaper
   alternative: seed `finishedAt` from `completedOneTime` on load. Rejected:
   there is no tick to seed it with, and a made-up tick would print a wrong
   delta; a blank is honest and lasts one life.
4. *A book's numbers can change between versions* (naysayer). Objection: a
   time from an older `bookVersion` is compared as if the book were the same.
   Cheaper alternative: drop `lastFinish` when `bookVersion` changes. Rejected
   for now: `completionCounts` and the chip counts already carry across
   versions the same way, and a book edit that changes a row's time is exactly
   what the player would want to see as a delta.
5. *`lives` stays uncapped* (naysayer). Objection: the save grows without
   bound. Rejected as out of scope: this change no longer adds to `lives`
   (Revision 1); the cap is a separate question for the lives list itself.

- [ ] **`blankRun`** (`queue.ts:21`) returns `finishedAt: {}` and

- [ ] **`complete()`** (`queue.ts:238`): the event becomes
  `{ type: 'completed', actionId, oneTime, ...(action.isOneTime && s.lastFinish[action.id] !== undefined ? { lastAt: s.lastFinish[action.id] } : {}) }`,
  and beside the `completedOneTime` append,
  `finishedAt: { ...s.finishedAt, [action.id]: s.runTicks }`.
- [ ] **`rebirth`** (`rebirth.ts:61`): `lastFinish: { ...dead.lastFinish, ...dead.finishedAt }`.
  `finishedAt` comes from `blankRun`.
- [ ] **Classification** (`rebirth.test.ts:149`): `finishedAt` joins
  `RESETS`, `lastFinish` joins `DERIVED`. `deadLife()` (`rebirth.test.ts:12`)

    Assert rig's core exp after life 1 is above 0 and the tick is smaller.
- [ ] **Property invariants** (`property.test.ts:160-185`, beside the
